# Streaming AI Telemetry

A production-style streaming data platform that simulates telemetry generated by modern AI applications and demonstrates real-time processing, cloud storage, analytics, and observability using Apache Kafka, Apache Flink, Amazon S3, Amazon Athena, Grafana, and Apache Spark.

The project is designed to learn streaming systems from first principles while following production-quality software engineering practices. It complements the Enterprise RAG & Agentic AI Platform by focusing on the infrastructure responsible for transporting, processing, and analyzing AI telemetry rather than AI inference itself.

---

## Motivation

Modern AI applications generate enormous amounts of operational telemetry.

Every inference request produces information such as:

* Request metadata
* Model used
* Latency
* Token usage
* Retrieval latency
* Tool calls
* Success or failure status

This telemetry is critical for:

* Monitoring production systems
* Detecting failures
* Measuring performance
* Capacity planning
* Cost analysis
* Historical reporting

Rather than processing these events synchronously, production systems stream them through scalable event pipelines.

This project demonstrates how a modern AI telemetry platform can be built using Kafka, Flink, Spark, Amazon S3, Athena, and Grafana.

## Milestone 1

Completed

### Objectives
- Design a stable domain model for AI inference telemetry.
- Implement a transport-independent serialization layer.
- Establish a foundation that can be reused by Kafka producers, Flink consumers, and Spark batch jobs.

### Key Design Decisions

- Used immutable (`frozen=True`) dataclasses to represent telemetry events.
- Modeled the domain using composition rather than inheritance.
- Kept the serializer independent of Kafka and other transports.
- Exposed a minimal public API:
  - `serialize(event) -> bytes`
- Used JSON as the wire format for simplicity and interview readability.
- Used UTF-8 encoding for portability and interoperability.
- Used `dataclasses.asdict()` internally while keeping dictionaries hidden from the public API.
- Explicitly reconstructed domain objects during deserialization instead of using reflection to improve readability and maintainability.
- Chose fail-fast deserialization for malformed JSON and invalid enum values.

### Testing

Implemented unit tests covering:
- Round-trip serialization/deserialization
- Byte serialization
- Invalid JSON handling
- Invalid enum handling

All tests passing.

### Milestone 2 - Synthetic Telemetry Generator

Completed

Implemented a configurable synthetic telemetry generator capable of producing realistic AI inference events for downstream streaming and analytics.

### Architecture

```text
                    Simulation Profile
                           │
                           ▼
             SyntheticTelemetryGenerator
                           │
                           ▼
             InferenceTelemetryEvent
                           │
                           ▼
               TelemetrySerializer
                           │
                           ▼
                     JSON (bytes)

```

### Features

- Added a static provider catalog containing supported AI providers and models.
- Introduced configurable simulation profiles to model different workload scenarios.
- Implemented a synthetic telemetry generator that produces internally consistent inference events.
- Generated realistic request metadata including request IDs, tenant IDs, session IDs, provider, model, and region.
- Modeled prompt and completion token relationships for realistic token usage.
- Simulated RAG metrics including retrieved chunks, reranked chunks, cache hits, and tool calls.
- Generated correlated performance metrics including retrieval, rerank, LLM, and total latency.
- Simulated request outcomes with configurable failure rates and realistic error generation.
- Added unit tests covering generator invariants and event validity.

### Key Design Decisions

- Separated static provider metadata from workload behavior.
- Profiles define workload characteristics while the generator is responsible for producing events.
- Derived metrics are computed from independent variables to maintain realistic relationships between telemetry fields.
- Profile validation is performed during object creation to prevent invalid configurations.
- Serialization remains independent of event generation, enabling future integration with Kafka and other downstream systems.

### Objectives

- Consume AI telemetry events from Kafka in real time.
- Process and transform telemetry streams.
- Demonstrate keyed and stateful stream processing.
- Compute real-time operational metrics.

### Architecture

```text

  │

```

### Features
- Added PyFlink Kafka source.
- Consumed telemetry events directly from the Kafka topic.
- Deserialized JSON telemetry events.

- Implemented stream transformations using map.
- Implemented keyed processing using key_by.
